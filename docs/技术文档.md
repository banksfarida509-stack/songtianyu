# AI 招聘副驾 · 技术文档

版本 0.1.0 · 2026-10-11

本系统由两部分组成：一个运行在招聘专员 Chrome 里的**浏览器插件**，和一个部署在服务器上的**后台服务 + 管理后台**。插件只在专员本人已登录的招聘平台页面里读取数据、展示 AI 结论、执行专员点击确认的动作；所有判断、约聊建议、排程都在后台完成。

- 管理后台：`http://101.201.77.185/hr/`（与学员系统 `http://101.201.77.185/` 并行，互不影响）
- 产品 Demo（静态演示）：`http://101.201.77.185/hr-demo/`
- 代码仓库：`github.com/banksfarida509-stack/songtianyu`

---

## 1. 总体架构

```
招聘专员的 Chrome（已登录智联企业版）
 ├─ inject.js  （页面主环境，只读）读取推荐卡片 Vue 组件数据、聊天 Vuex 状态
 ├─ content.js （隔离环境）画卡片上的 AI 结论行、右下角副驾面板
 └─ background.js（扩展后台）带令牌调用后台 API
            │  HTTPS/HTTP + X-HR-Token
            ▼
nginx :80 ──/hr/──▶ hr-agent（Node 24，127.0.0.1:3100，pm2 管理）
                     ├─ 规则引擎（初筛结论，确定性）
                     ├─ AI 层（推荐理由、约聊回复建议）──▶ 学员系统 AI 网关 /api/llm-gw
                     ├─ 排程（AI 约到场时段；前台当天分配面试官）
                     └─ SQLite /opt/hr-agent/data/hr.db
       ──/────▶ 学员系统（原有，:3000）
       ──/hr-demo/─▶ 静态 Demo
```

设计原则：

1. **只读本账号能看到的数据，不额外向平台发请求。** 插件读取的是页面已经加载好的数据（组件 props / Vuex 状态），不调用平台接口、不翻页爬取、不多账号轮换。
2. **结论由规则给出，大模型只写理由和回复草稿。** 初筛的“推荐 / 待确认 / 不推荐”来自规则引擎，可追溯；大模型不能改结论。
3. **人在环中。** 插件不会自动发送消息：回复填入输入框后由专员点“发送”；“按推荐顺序打招呼”需专员二次确认，且每位间隔 15–30 秒、检测到平台风控提示立即停止。
4. **零第三方依赖。** 后台只用 Node 24 内置模块（`node:http`、`node:sqlite`、`node:crypto`），部署不需要 `npm install`。

## 3. 浏览器插件

### 3.1 页面数据读取（智联 rd6.zhaopin.com，2026-10-11 实测）

| 页面 | 读取位置 | 字段 |
|---|---|---|
| 推荐人才 `/app/recommend` | 每张卡片 `.recommend-item__inner` 上方 Vue 组件的 `$props.candidate` | resumeNumber、userName、age、educationLevel、workYears、careerStatus、desiredSalary、workExperiences（单位、职位、起止）、educationExperiences（学校、专业、学历、学校标签）、skillTags、certificateNames、selfEvaluation |
| 推荐人才 | `$store.state.jobs.jobList` + URL `jobNumber` | 当前岗位名称 |
| 聊天 `/app/im` | `$store.state.im.activeSessionId`、`currentSession`、`timelineMap[sessionId].timeline` | 会话候选人、简历编号、岗位；文本消息（`flow` 区分收发） |

字段白名单在插件（`inject.js → pick()`）和后台（`rules.js → normalizeZhaopin()`）各做一次：头像、手机号等一律不读、不传、不存。

智联页面不提供教师资格证（实测 20/20 为空），由 AI 约聊追问后写入“已知信息”。

### 3.2 插件做什么

| 页面 | 自动（只读） | 专员点击后才执行 |
|---|---|---|
| 推荐人才 | 读取卡片 → 后台初筛 → 每张卡片底部显示“AI 推荐 / 待确认 / 不推荐 · 分数 · 理由”；右下角面板按分数排序 | “按推荐顺序打招呼”：二次确认后逐个点卡片上的“打招呼”，间隔 15–30 秒，可随时停止 |
| 聊天 | 候选人发来新消息时，自动请求 AI 回复建议，显示两道检查结果和建议动作 | “填入输入框”（专员再点平台“发送”）；“点「约面试 / 换微信」”打开平台原生窗口；“我已发送”把约聊结果写入人才池 |

风控熔断：页面出现“操作频繁 / 安全验证 / 滑动验证 / 账号异常”等提示时，插件停止一切自动动作并提示专员。

### 3.3 安装

后台“设置 → 浏览器插件 → 下载插件”得到的 zip 已内置服务器地址和令牌。Chrome 打开 `chrome://extensions`，开启开发者模式，“加载已解压的扩展程序”选择解压后的 `hr-agent-extension` 文件夹。服务器地址变化时可在插件选项页修改。

### 3.4 适配风险

插件依赖智联前端的 Vue 2 组件结构和 Vuex 字段名。智联改版时需要更新 `inject.js` 的选择器和字段映射。BOSS 直聘尚未实测，插件目前只在 `rd6.zhaopin.com` 生效。

## 4. 后台服务

### 4.1 初筛规则（`rules.js`，可在后台“设置”修改）

| 编号 | 规则 | 不满足时 |
|---|---|---|
| R01 | 年龄 ≤ 上限（默认 35） | 不推荐 |
| R02 | 学历 ≥ 最低学历（默认本科） | 不推荐 |
| R03 | 专业 / 职位 / 技能命中科目关键词 | 不推荐 |
| R04 | 有学校教学经历，或毕业于师范 / 教育类专业 | 只有培训机构经历或应届非师范 → 待确认；完全无教学经历 → 不推荐 |

| R05 | 意向型（可关）：学历 ≥ 本科、年龄 ≤ 30、求职方向含“教师 / 教学 / 老师 / 助教 / 讲师 / 教研 / 班主任”，且没有学校教学经历 | 满足时放宽 R03、R04，判“推荐”，分数封顶 66 |

分数 = 55 + 学校教学经历 12 + 师范 8 + 985/211/双一流 8 + 年限（每年 4，最多 3 年） + 硕士及以上 4 + 有教师资格证 4 − 仅机构经历 6；“不推荐”封顶 40。字段缺失（如页面没显示年龄）判“待确认”而不是“不推荐”。改规则后可“按新规则重新初筛全部”。求职方向由插件从卡片的 `desiredJobType / preferredJobType / desiredJobTypeHighlights` 等字段收集文字（字段名以实测为准）。

**投递者先看简历再回复（v0.9.7）**：实测发现，消息页里投递者大多被判成“待确认（仅有聊天记录，未读取简历）”，原因是插件只在聊天变化时读一次简历，而智联的简历（`im.activeResume`）加载得比聊天内容晚。现在：
- 优先读 `activeResume`；打开会话后最多等 8 秒简历再交给 AI。简历更晚才出现、回复还没发出时，带上简历重新判断。
- 后台唤醒改为每 30 秒一次，每次唤醒都让页面立即读一遍聊天（后台标签页里，页面自己的定时器大约每分钟只跑一次）。
- 回复规则：投递者符合 / 待确认的，先用学校资料回答对方投递时的提问，没提问的就介绍一个相关的岗位亮点，然后问一个基本情况。不符合的礼貌婉拒，第一条回复时还没读到简历、之后才判不符合的，下一条回复婉拒（`lateDecline`）。但会话里同事亲自回复过、已约面试、已经结束的不自动婉拒；我们先打招呼的会话也不自动婉拒。
- 聊天记录里区分人工消息（`human`：从页面读回来、又不是 AI 自己发的那条），AI 发出后又从页面读回来的同一条只算一次。

**教师岗统招全日制本科（v0.9.6，`rules.requireTongzhaoBachelor`，默认开）**：规则 R06（`bachelorCheck`）判以下几种为不推荐：
- 专升本：本科之前有大专经历（学历写“大专”，或学校名是职业学院 / 高等专科学校…）；本科毕业后读的“大专”（如国外语言学校）不算。
- 本科只读了 2 年或更短（入学到毕业年份相差 ≤ 2）。
- 本科都标着非统招 / 自考 / 成人 / 函授等。
- 最高学历低于本科。
简历里没有本科的详细信息时不加这条。学历类规则（教师 R02、R06；学管师、课程顾问 R02、R05 统招）和毕业年份 G01 都是硬规则（`hard: true`）：AI 按岗位备注复核不放宽，之前 AI 放宽过的结论在重新初筛时也会被推翻。2026-10-14 上线时，人才池里 62 位教师岗（专升本 / 非统招）由推荐、待确认改为不推荐；实测发现 AI 曾按备注把其中几位放宽成推荐。

**v0.9.4（2026-10-14 首次真实页面运行后的修正）**：
- 防重复回复：自动发送前调用 `POST /api/ext/chat/claim {candidateId, sig, by}`（sig = 会话 ID + 最后一条消息 ID）。同一条消息，只有先领到号的页面可以发；其他页面、其他浏览器都会放弃（实测开着两个消息页时，同一条消息被回了两次）。领号在内存里保留 30 分钟。
- 已读未回复：巡检处理完未读后，会把最近 3 天有动静的会话（`sortTime / communicateTime / lastActiveTime`）每个打开一次；对方最后一条没回复的，按正常流程回复（之前只看未读，被点开看过但没回的会话一直没人处理）。
- 智联推荐卡片实测没有同事沟通的字段，卡片上也没有这类文字（候选人对象里只有 `isChatted / chatting`，指本账号）。“同事聊过”目前在智联只能靠系统里的沟通记录判断。读卡片文字时先复制卡片并去掉我们的 AI 行，避免把自己加的标签读回来（v0.9.2 实测 20 张里误判了 11 张）。BOSS 解析卡片文字时也去掉 AI 行。
- 毕业年份：智联卡片读 `userGraduateDescription`，再看卡片文字，最后看 `isSchoolResume`（在校生，按明年毕业算）。推荐页诊断 `rec.gradSample` 上传前 8 张卡片的这几个字段，用来核对。

**毕业年份硬规则（v0.9.3，所有岗位）**：`rules.maxGradYear`（默认 2026，0 = 不限）。毕业年份取自教育经历的结束时间；结束写“至今 / 在读”的，按入学年份加学制（本科 4、大专 3、硕士 3、博士 4 年）推算；都没有时，读卡片上的“27届 / 2027年毕业 / 27年应届”或毕业字段（`gradText`）。只有开始时间的不推算。毕业年份晚于上限的判“不推荐”（规则 G01，`hard: true`），AI 按岗位备注复核不会放宽这类人。

### 4.2 AI（`ai.js`、`llm.js`）

- **接口**：调用学员系统 AI 网关 `{CP_URL}/api/llm-gw/{provider}/v1/chat/completions`（OpenAI 兼容），鉴权用学员系统租户自己的 `TENANT_ID:TENANT_API_TOKEN`，费用计入该租户余额。后台启动时只从 `/opt/xiyejia-training/.env` 读取这三个值，不复制任何模型厂商的 Key。
- **模型**：主 `deepseek / deepseek-chat`，备 `bigmodel / glm-4-flash`（2026-10-11 实测两者均可用），可在后台设置修改。
- **换成自有 Key**：在 `/opt/hr-agent/.env` 填 `HR_LLM_DIRECT_URL`、`HR_LLM_DIRECT_KEY`（OpenAI 兼容），重启后优先使用。
- **推荐理由**：插件先拿到规则理由（即时），再批量请求 AI 改写成一句话理由（约 3–10 秒），失败则保留规则理由。
- **约聊回复**：大模型输出 `{intent, slots, reply}`；状态推进由代码决定：
  - 意图“约面时间” → 后台按候选人说的上午 / 下午找最近可约时段，回复改写为固定句式，建议动作“约面试”；
  - “确认参加 / 改期 / 拒绝” → 专员点“我已发送”后更新人才池；
  - “议价 / 要求真人” → 转人工；
  - “交换联系方式” → 建议点平台“换微信”，消息里不写联系方式。
- **发送前两道检查**（任一命中即不允许填入、转人工）：
  - 我方护栏：承诺词（保证 / 一定）、限制性表述（年龄性别婚育户籍）、回复中的数字必须出自知识库或已约时段；
  - 平台拦截规则：取自智联聊天页内置规则（6 位以上连续数字、公众号、支付转账、投资虚拟币、第三方聊天软件名等）。
- **AI 不可用时**：自动回退到关键词规则，系统照常可用，界面标注“规则回退”。

### 4.2.1 约聊回复方式：全自动 / 半自动 / 转人工（v0.2.0）

候选人每条消息先由 AI 分类（提问、提供信息、约面时间、确认参加、改期、拒绝、议价、要求真人、交换联系方式、其他），再由 `decideMode()` 决定处理方式：

| 顺序 | 判断 | 结果 |
|---|---|---|
| 1 | 回复没通过发送前检查 / AI 判定需转人工（议价、要求真人、时段已满） | 转人工 |
| 2 | 本会话单独设置（插件面板：按分类 / 半自动 / 全自动 / 转人工） | 覆盖分类设置 |
| 3 | 分类设置（后台“设置 → 约聊回复方式”，默认：议价 / 要求真人转人工，交换联系方式 / 其他半自动，其余全自动） | 全自动 / 半自动 / 转人工 |
| 4 | 全自动前置条件：总开关已开（默认关）、在自动回复时段内（默认 08:30–21:00）、未超每小时上限（默认 40）、AI 可用（规则回退时只有固定流程类意图可自动） | 不满足 → 半自动 |

- **全自动执行**（插件）：等待 `delayMin–delayMax` 秒（默认 25–90）加上按字数估算的打字时间，倒计时期间可“立即发送 / 取消”；输入框分段写入，较长回复有时拆成两条、间隔 1.5–4 秒；输入框里有专员正在写的内容时不发送；发送后核对输入框清空，再记录到人才池（`messages.by = 'ai-auto'`）。需要平台动作（约面试、换微信）的，文字自动发出，动作进入“待你处理”。
- **巡检**：总开关开且勾选“自动打开有未读消息的会话”时，插件空闲时每 15 秒打开下一个有未读消息的会话；专员 45 秒内操作过页面时不切换；当前会话有未处理的半自动建议时，3 分钟后才切换（该会话留在“待你处理”列表）。
- **真人感**：系统提示词带“回复风格”（后台可改），温度 0.6；固定流程的回复（约时间、确认、改期、拒绝、换微信）每类有多种说法随机选用。被问是否机器人时仍如实说明是 AI 招聘助理。
- **知识库**：见 4.2.2。回复里出现的数字必须能在本次取到的资料段落、问答或已约时段里找到。

### 4.2.2 知识库文档、身份与重复提问（v0.3.0）

- **身份**：AI 以“设置 → AI 对候选人的身份”（默认“招聘约访官，同时负责初试面试”，可设称呼如“王老师”）第一人称回复，直接回答薪资、待遇福利、作息时间等问题；资料里没有答案时回“我核实一下晚点回复你”并转人工（`unknown`）。候选人明确问是否真人 / 机器人时如实说明。
- **文档**（表 `kb_docs`：标题、来源、内容、启用）：后台“知识库”页上传 Word(.docx) / PDF / Excel(.xlsx/.xls) / txt / md / csv，可多选、可拖拽；文字在浏览器端提取（mammoth、pdf.js、SheetJS，从 cdnjs 按需加载，失败时换 jsDelivr），单文档最多 50 万字；可编辑、停用、删除；插件选项页可新建文字文档、上传 txt/md、查看列表。旧版“整段粘贴”的内容在首次启动时自动转成文档“知识库（粘贴）”。
- **检索**（`kb.js`）：文档按段落切成约 420 字的段，按中文二元词 + IDF 打分，并按主题扩展同义词（如“作息时间”扩展“上班 下班 坐班 晚自习 双休”）；每次回复取最相关的最多 6 段、3200 字放进提示词。后台“检索测试”可看某句话会命中哪些段落。
- **从历史约聊学习**：聊天页面板“采集历史约聊”依次打开最近 N 个会话（默认 30，最多 50）读取记录上传（`POST /api/ext/chat/history`，只读不发送，跳过有未读消息的会话）；后台“知识库 → 从历史约聊学习”（`POST /api/kb/learn`）把“候选人问题 → 当时的回复”交给 AI，按主题（薪资、待遇福利、作息时间优先）归纳出现次数、典型问法和标准答案（只用当时回复里的事实，缺的标“待补充”），专员核对后“加入知识库”。
- **重复提问**：每条候选人问题记录主题（`messages.topic`）。当前问题与之前的问题“措辞高度相似”，或“主题相同且措辞相近”，或模型判断 `askedBefore`，计为再次提问；达到“同一问题问到第几遍转你本人”（默认 2）时转人工，不自动回复。
- **连发消息**：候选人连续发几条时，自动回复倒计时内收到新消息会重新生成，一次回应全部未回复的消息。
- **约访全流程（v0.4.0）**：
  - 插件判断会话来源：时间线第一条是候选人发的（或含投递卡片）→ “主动投递”；第一条是我们发的 → “我们打招呼”。在聊天页的 Vue 组件 / 会话对象里查找简历对象（含 `workExperiences / educationExperiences` 等），找到后按初筛规则判定。
  - 对主动投递者的第一条回复按初筛结论分为“投递-符合”（感谢 + 亮点 + 直接邀约，给出最近上午 / 下午可约时段）、“投递-不符合”（礼貌婉拒，不说具体原因，人才池标“不合适”）、“投递-待确认”（问一个关键信息），三类默认全自动。
  - 我们打招呼后对方回复：按知识库和“我的沟通话术”回应；对方有意向时主动给出可约时段邀约。
  - 约定时间后（全自动且开启“自动发送面试邀约”）：文字回复发出后，插件点平台「约面试」，在弹窗里按组件类型填入面试时间（日期 / 时间选择器用 `$emit('input')`）、空的地点填学校地点，点发送，并核对弹窗关闭；没能自动提交时弹窗留给专员，会话进入“待你处理”，同时把弹窗结构（字段标签、组件名、按钮文字，不含个人信息）上报到 `settings.diag_invite`。专员手动发一次邀约时也会记录弹窗结构，用于校准。
  - “我的沟通话术”（`settings.playbook`）：“从历史约聊学习”时，用专员亲手发的消息（`by='staff'`，排除 AI 发的）总结整体风格、投递合适 / 不合适时怎么说、打招呼后怎么接、怎么引导约面、常用说法；后台“知识库”页可编辑、可停用。
  - 面板“复制诊断信息”：复制当前会话对象的字段结构（只有字段名和类型）、消息类型、是否找到简历、页面按钮文字和最近记录的邀约弹窗结构，用于适配。
- **多岗位（v0.6.0，`roles.js`，`settings.roles`）**：教师 / 学管师 / 咨询师。按平台职位名识别岗位（先匹配学管师、咨询师关键词，其余归教师），候选人记录 `candidates.role`。
  - 初筛：教师沿用原规则；学管师、咨询师用 `screenRole`：R01 年龄、R02 学历（默认大专）、R03 相关经历（职位 / 公司名命中经历关键词）、R04 求职方向。有相关经历 → 推荐；无经历但求职方向对口且年龄在“意向型年龄上限”内 → 推荐（意向型，分数封顶 68）；其余较年轻 → 待确认，否则不推荐。
  - 约聊：每个岗位一组“依次了解的问题”（教师：在职、住处、科目、开始工作时间；学管师：在职、住处、教育 / 客服类经验、能否周末上班、开始时间；咨询师：在职、住处、销售经验、能否接受底薪加提成、开始时间）和“岗位沟通要点”，写进提示词；AI 输出的已知信息字段按岗位问题生成。
  - 知识库：文档有“所属岗位”（`kb_docs.role`：all / teacher / xueguan / zixun），检索时只取“通用 + 本岗位”。首次启动为学管师、咨询师各插入一份停用的【模板】文档（职责、要求、作息、薪资、培训发展、地点、常见问题），填写后启用。
  - 后台：“设置 → 岗位配置”可改职位关键词、初筛规则、问题和沟通要点，可一键按新规则重新初筛；“知识库”页可选择上传到哪个岗位、逐份修改所属岗位；人才池显示岗位标签。
- **主动跟进（v0.7.0，`followup.js`，`settings.autoReply.followup`）**：
  - 打招呼跟进：推荐页打招呼成功时记录 `candidates.greeted_ms`；满 `greetHours`（默认 3 小时）仍没有任何回复 → 跟进一次（每人只一次）。
  - 已读不回跟进：会话里对方回复过，我们发出最后一条后满 `readHours`（默认 1 小时）无回复，且最后一条显示“已读”（`onlyIfRead`，读消息对象的 read 字段或页面上的“已读 / 未读”标签）→ 跟进一次；对方回复后再次冷场可再跟进；每人累计最多 `maxTotal`（默认 3）次。
  - 不跟进：确认参加、不来、不合适、转人工；全自动未开或不在自动回复时段。
  - 执行：插件巡检没有未读会话时，每 2 分钟取一次到期名单（`POST /api/ext/followups`），打开会话（`openBy`），确认最后一条仍是我方消息并读取已读状态，再取跟进内容（`POST /api/ext/followup/draft`，服务端再次核对），分类“跟进”按全自动规则发送；发送后记录到 `candidates.followup_json`。同一人 15 分钟内不重复尝试。
  - 话术：AI 按岗位和知识库写 1–2 句；打招呼跟进点一个岗位亮点 + 一个好回答的问题，不催促；已读跟进问顾虑 / 想了解什么，并再给一次面试时间。数字必须出自资料或可约时段，否则用模板。
- **消息页保活与持续打招呼（v0.9.0）**：
  - 问题（2026-10-14）：自动回复、未读巡检、主动跟进只在「消息」页（智联 `/app/im`、BOSS `/web/chat/index`）运行；专员只开着推荐页时，16 条未读三天无人回复。
  - 心跳：`/api/ext/ping` 带 `platform` 和 `kind`（im / rec），按“平台:页面”记在 `settings.ext_pages`；返回 `imAlive`（3 分钟内有消息页心跳）。推荐页面板在消息页未运行时显示红色提示和“打开消息页”按钮；总览新增“插件运行状态”卡片。
  - 保活（`background.js`，`settings.autoReply.keepImTab`，默认开）：全自动开启且某平台 3 小时内用过时，每分钟检查一次；没有消息页就打开一个固定（pinned）标签页，关掉了会重开；设为不自动丢弃；并发 `wake` 消息触发巡检（后台标签页的定时器会被 Chrome 降到约每分钟一次）。
  - 持续打招呼（`settings.greet`）：每个平台、每个岗位每天的上限（默认 教师 100、学管师 50、课程顾问 50、其他 30），岗位按推荐页当前职位名识别（`roleFor`），计数记在 `greet_log` 表。持续模式打完一批自动接着打，直到上限或没有更多推荐；智联打招呼后跳到别的页面会自动返回推荐列表；被中断（刷新、插件更新）后，当天再打开推荐页会在 10 秒后自动继续。每次停止的原因上传到 `diag_greet`（`GET /api/diag` 可读最近 10 次）。
  - 新接口：`POST /api/ext/greet/quota`；`/api/ext/greeted` 返回 `quota`。
  - 同事聊过的最后打（v0.9.2）：每张推荐卡片带 `peerChat`。BOSS 读卡片数据的 `mateName`；智联读候选人对象里名称像“同事”的字段（colleague / coworker / mateName …），以及卡片上“同事…沟通过 / 联系过”之类的文字（都不含我们自己的 AI 行）。服务端 `/api/ext/screen` 返回 `peer`：卡片标记，或系统里已有这个人的打招呼 / 聊天记录。打招呼先打同事没聊过的；当前页没有了就加载更多，连续 4 次都没有，才开始打同事聊过的。卡片 AI 行显示“同事聊过 · 最后打”。智联具体用哪个字段还没在真实页面确认：推荐页诊断（`diag_rec.data.page.rec`）上传卡片字段名、卡片上的相关短标签和识别到的人数，用来核对。
- **新接口**：`POST /api/ext/greeted`、`POST /api/ext/followups`、`POST /api/ext/followup/draft`、`POST /api/ext/diag`、`POST /api/ext/chat/invited`、`GET /api/diag`、`GET/POST/PATCH/DELETE /api/kb/docs[/:id]`、`POST /api/kb/search`、`POST /api/kb/learn`、`GET /api/ext/kb`、`POST /api/ext/kb/docs`、`POST /api/ext/chat/history`。
- **接口**：`GET/PUT /api/ext/kb`、`POST /api/ext/chat/mode`；`/api/ext/chat/suggest` 返回 `decision {mode, why, delayMs}`；`/api/ext/chat/applied` 接受 `auto: true`；`/api/ext/ping` 返回 `auto` 状态。

### 4.3 面试排程（`schedule.js`）

- AI 只约**到场时段**：上午 09:00–11:00、下午 13:00–15:00，每半小时一档，每档默认最多 4 人，只排工作日（均可在设置修改）。
- 自动排程：把“待排程”的候选人按初筛分从高到低，放进偏好半天（上午 / 下午 / 全天）里最近的未满时段；偏好“需人工”的不排。
- **面试官由前台当天分配**：只有面试当天可以点“分配”，列表显示每位面试官“空闲 / 面试中”；面试中的不可选（后端同样校验）。“结束”后面试官恢复空闲，可标记“未到场”。
- 面试地点统一（默认“学校本部”）。

### 4.4 数据表（SQLite）

| 表 | 用途 | 关键字段 |
|---|---|---|
| candidates | 候选人（平台 + 简历编号唯一） | 简历白名单字段、verdict / score / reason / reason_by、attend（约聊结果）、slots_json（AI 抽取的资格证、到岗、时段偏好）、handoff、is_demo |

| interviewers | 面试官 | name、active |
| messages | 约聊消息 | dir（in/out）、by（candidate/ai/staff）、text |
| events | 时间线 | at、text |
| settings | 配置 | org、rules、schedule、ai、kb、greet、ext_token、session_secret、ext_last、ext_pages |
| greet_log | 推荐页打招呼记录（每日上限计数） | day、platform、role、uid、at |

约聊结果（attend）：未联系 → 沟通中 → 待排程 → 待确认 → 确认参加；以及 改期中、不来、未回复。

## 6. 安全与合规

- 插件令牌只用于插件接口，可在后台一键更换；管理后台用 HttpOnly 会话 Cookie。
- 简历字段白名单，不存照片和联系方式；示例数据可一键清空。
- 不自动发送消息，不绕过平台验证，不多账号轮换；出现风控提示立即停止。
- 学员系统 AI 网关按租户计费，用量计入学员系统余额；余额不足时 AI 自动回退到规则。
- 当前为 HTTP，后续建议给服务器配域名和 HTTPS。
